# История изменений YANIME

Файл `yanime.json` — основной источник курируемой истории версий YANIME.
Для каждой версии добавляйте отдельный объект в массив `releases`.

## Обычные записи

Поле `notes` содержит короткие пользовательские изменения. Пишите по-русски,
начинайте с результата для пользователя и избегайте внутренних технических
подробностей. Один пункт — одно самостоятельное изменение.

## Привязка записи к коммиту

Если пункт относится к конкретному коммиту, добавьте его в
`commit_overrides` внутри объекта нужной версии:

```json
{
  "sha": "98adb1e156b357f665ae35c3be4d6ffdda19154e",
  "tag": "UI",
  "title": "Фильтр серий: сохранение выбранного режима и позиции списка",
  "description": "Выбранный режим сохраняется между запусками приложения. При переключении фильтров список возвращается к той же серии."
}
```

- `sha` — полный SHA коммита из GitHub, без URL.
- `tag` — исходный тег коммита без квадратных скобок. Не переименовывайте его.
- `title` — новая формулировка вместо исходного заголовка коммита.
- `description` — необязательное короткое пояснение; можно опустить.

Такой текст заменяет заголовок и описание исходного коммита в автоматически
собираемой истории и карточке релиза GitHub. В приложении он отображается
в истории версии, к которой привязан. Тег коммита сохраняется.

## Стиль текста

Ориентируйтесь на формулировки Helandy: короткий предметный заголовок,
при необходимости — область изменения и двоеточие, затем суть. Например:
`Новости (мобилка): постер целиком на размытом фоне вместо обрезки`.

Не добавляйте точку в конце заголовка. Описание должно объяснять заметный
результат или важное поведение, а не пересказывать реализацию.
